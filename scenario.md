# СЦЕНАРИЙ И ТЕХНИЧЕСКАЯ ДОКУМЕНТАЦИЯ ИГРЫ «СИГНАЛ-9»

## ЧАСТЬ 1: ПОДРОБНЫЙ СЦЕНАРИЙ И ПРОХОЖДЕНИЕ

### ВВЕДЕНИЕ
Игрок выступает в роли автономного ИИ-модуля станции «Сигнал-9». Главная глобальная цель игры — восстановить работоспособность станции и найти ключ-пароль для дешифровки сигнала, чтобы станция снова могла «читать» данные. Управление происходит через выпадающую консоль (`~`) и системный журнал.

### ЭТАП 1: АВТОРИЗАЦИЯ (`login.html`)
1. **Задача:** Нарисовать Трассит (графический ключ).
2. **Решение:** Ключ — слово «ТРАССИТ». Узнать его можно в консоли через `help login` -> переход в `tools.html`, где в режиме «Текст» можно ввести «ТРАССИТ» и посмотреть порядок точек. Затем вернуться и соединить их.
3. **Результат:** Появляется надпись «ДОСТУП РАЗРЕШЕН», ставится `s9_access_granted = true`, переход на `index.html`.

### ЭТАП 2: ЯЗЫКОВОЙ СБОЙ (`index.html`)
1. **Интерфейс:** Глифы трясутся, текст `ERR_DATA`, телеметрия в машинном коде.
2. **Журнал:** Ошибка `AttributeError: 'DigitalBeing' object has no attribute 'human_lang'`. Автоматически открывается консоль.
3. **Решение:** Ввести `system --help`, затем `system --lang human`.
4. **Результат:** `s9_lang_human = true`, страница перезагружается, интерфейс становится на русском.

### ЭТАП 3: ЗАШИФРОВАННЫЙ СИГНАЛ (`index.html` -> `map.html`)
1. **Интерфейс:** Интерфейс на русском. Глифы крутятся, но **подписи под ними — это недешифрованный мусор** (зашифрованный текст). Журнал сообщает, что ключ-пароль отсутствует.
2. **Действие:** В консоли ввести `map`.
3. **Карта:** Узел «БАЗА ДАННЫХ» (Архив) горит красным (`ERROR`). Архив переполнен. Ввести `archive`.

### ЭТАП 4: ОБУЧЕНИЕ АРХИВА (`archive.html` -> `tools.html`)
1. **Архив:** Выдает ошибку буфера. Журнал просит обучить автосохранение в Инженерном терминале.
2. **Действие:** Игрок переходит в `tools.html` (по команде `terminal`). В консоли вводит `help archive` (получает наводку на `archive --traning`).
3. **Обучение:** Вводит `archive --traning` (терминал желтеет). В консоли вводит `archive --traning word`, чтобы получить список из 5 слов (ХАБ, ГЛИФ, ПУЛЬТ, СЕРВЕР, КОНСОЛЬ).
4. **Механика:** Игрок вводит слово в режиме «Текст» (смотрит на эталон), переключает тумблер на «Трассит» и рисует глиф. Система засчитывает **только нарисованный** глиф.
5. **Результат:** После 5 слов ставится `s9_archive_calibrated = true` (терминал синеет). Архив получает 1 базовую фразу.

### ЭТАП 5: НАКОПИТЕЛЬНЫЙ БУФЕР И ОС (`archive.html` -> `os.html`)
1. **Архив:** Игрок заходит в Архив. Видит вкладки «НАКОПИТЕЛЬНЫЙ БУФЕР» и «СЕКТОР ВЕРИФИКАЦИИ».
2. **Ожидание:** В Буфере накапливаются фразы. Сектор верификации выдает «ОШИБКА ВЕРИФИКАЦИИ. КЛЮЧ-ПАРОЛЬ НЕ НАЙДЕН».
3. **Переход:** Как только накапливается 3 фразы (1 базовая + 2 новые), ставится `s9_archive_fixed = true`. ОС на карте становится доступной.
4. **ОС:** Переход в `os.html`. Консоль блокируется. Ввод `login --id 0x7f930cb4ddb0` (или через `self --id`). Чиним 7 кубитов командой `os --reset qubit rXcY`.
5. **Сбой:** После 7-го кубита — критический сбой. `s9_edr_os_trigger = true`. Переход в EDR.

### ЭТАП 6: EDR И РЕМОНТ ЯДРА (`edr.html` -> `map.html` -> `core.html`)
1. **EDR:** 3 этапа уравнений. Ввод `edr --answer <число>`. При успехе `s9_os_fixed = true`.
2. **Охлаждение:** На карте Ядро желтое. Чтение журнала (5 шагов) запускает таймер на 64 секунды (`s9_core_timer_start`). После перегрева Ядро краснеет (`s9_core_overheated = true`).
3. **Ядро:** Переход в `core.html`. Ввод `help core` (получение уравнений). Решение системы. Ввод `core --position rt [X], lt [-X]...` и `core --position sync`. Ядро зеленеет, `s9_core_fixed = true`, страница перезагружается. Телеметрия разблокирована.

### ЭТАП 7: ТЕЛЕМЕТРИЯ И КЛЮЧ (`telemetry.html`)
1. **Телеметрия:** 4 волны (Белая + RGB). Параметры генерируются случайно при загрузке.
2. **Решение:** Игрок использует `telemetry --read target`, `telemetry --set ...` и `telemetry --toggle ...` (или кликает по названиям волн). Значения ограничены безопасными лимитами (Clamp).
3. **Результат:** Волны синхронизируются, `s9_telemetry_calibrated = true`.
4. **ФИНАЛ (Задел на будущее):** Игрок получает Ключ-Пароль (Соль). При вводе ставится `s9_salt_found = true`. Мусор в глифах превращается в нормальный текст. Архив начинает верификацию.

*(Мертвые флаги `s9_emergency_*`, `s9_os_errors`, `s9_core_warning_read` полностью удалены).*

### 3. Механика шифрования (Подменная соль)
- **`js/glyph.js`**: Функция `getWrongLabel(word)`.
  - Если `s9_salt_found === 'true'`, возвращает нормальное слово.
  - Если слово есть в массиве `VOCABULARY` (5 эталонных слов), возвращает его (оно вшито в терминал).
  - Для всех остальных слов использует хэш-функцию с солью `7777` и выдает случайный набор кириллицы той же длины.
- Применяется в `core.js` (вывод глифов в Хабе), `archive.js` (вывод в буфере) и `tools.html` (вывод не-эталонных слов).

### 4. Логика Терминала (`terminal.js`, `tools.html`)
- **Punto Switcher Fix:** `keydown` проверяет `e.code === 'Backquote'`. Если фокус в `input`, консоль не закрывается (чтобы можно было печатать букву «ё»), но `Escape` всегда закрывает консоль.
- **Команды:** `help archive`, `help terminal` выводят наводки. `archive --traning` включает обучение. `archive --traning word` выводит список слов.
- **Режим Трассит:** В `tools.html` засчитывается только ручное рисование. При успехе глиф висит 3 секунды (`isTrainingSuccessAnimating = true` блокирует клики).

### 5. Логика Архива (`archive.js`)
- **НАКОПИТЕЛЬНЫЙ БУФЕР:** Принимает фразы из `sync.js`. Ждет, пока `phrases.length >= baseline + 2` (то есть 3 фразы). Затем ставит `s9_archive_fixed = true`.
- **СЕКТОР ВЕРИФИКАЦИИ:** Если `s9_salt_found !== 'true'`, сетка скрывается, поверх рендерится плашка `ОШИБКА ВЕРИФИКАЦИИ` с текстом об отсутствии ключа и ожидании сигнала с Хаба «СИГНАЛ-0».

### 6. Логика Ядра (`reactor.js`)
- `checkCorePosition` и `syncCore` доступны всегда.
- Если `s9_core_fixed === 'true'`, функции не ломаются, а пишут в консоль `[OK] ЯДРО СТАБИЛЬНО`.
- После `syncCore` страница перезагружается через 2 секунды (`location.reload()`).

### 7. Логика Телеметрии (`telemetry.js`)
- **Генерация:** `getRandomParams()` генерирует стартовые параметры для всех 4 волн в узком диапазоне (20..35 freq, -90..90 phase и т.д.).
- **Clamp:** В `telemetryCommand` при `--set` срабатывает ограничение: freq (0-100), phase (-180..180), amp (0-150), offset (-125..125).
- **Интерфейс:** Клик по тексту `RED WAVE` / `GREEN WAVE` / `BLUE WAVE` вызывает `toggleWave(color)`, который скрывает волну и глушит звук.
- **Аудио:** В `createAudioNode` используется `osc.type = 'triangle'`, фильтр `lowpass` (2000 Гц) и `detune = 10` для объемного хорового звучания.
- **Читы:** `window.cheatFixTelemetry()` и `window.cheatResetTelemetry()`.

### 8. Читы (`cheats.js`)
- `save` / `load <base64>`: работа с сохранениями.
- `fix_lang`: ставит `s9_lang_human`.
- `fix_archive`: выдает флаги обучения и починки, перекидывает в Архив.
- `calibrate_archive`: только калибрует (1 базовая фраза).
- `reset_archive`: чистит все флаги Архива, включая `s9_archive_training`.
- `fix_os`: ставит капчу, чинит кубиты. Если EDR пройден — чинит ОС. Если нет — вызывает EDR.
- `reset_os`: сбрасывает ОС и EDR.
- `reset_core`: сбрасывает Ядро в желтое состояние.
- `reset_telemetry`: генерирует новые волны (через `window.cheatResetTelemetry`).
- `clear_memory`: полная очистка `localStorage` (с подтверждением Y/N).

## ЧАСТЬ 1: ПОДРОБНЫЙ СЦЕНАРИЙ И ПРОХОЖДЕНИЕ

### ВВЕДЕНИЕ
Игрок выступает в роли автономного ИИ-модуля станции «Сигнал-9». Механика игры построена на взаимодействии с выпадающей консолью (тильда `~` или кнопка `>_`), через которую вводятся команды, и системным журналом (справа). Никаких кнопок на самом экране, кроме редких системных, нет. Все загадки решаются через ввод текста.

### ЭТАП 1: АВТОРИЗАЦИЯ (`login.html`)
1. **Интерфейс:** Игрок видит сетку из 9 точек. Журнал справа печатает приветствие и инструкцию.
2. **Задача:** Нарисовать Трассит (специальный графический ключ). 
3. **Решение:** Ключ — это слово «ТРАССИТ». Игрок может узнать его в консоли по команде `help login` -> `terminal` (переход в `tools.html`), где в режиме «текст» можно ввести «ТРАССИТ» и увидеть порядок точек. Затем вернуться на `login.html` и соединить точки в том же порядке.
4. **Результат:** Появляется надпись «ДОСТУП РАЗРЕШЕН», ставится флаг `s9_access_granted = true`, переход на `index.html`.

### ЭТАП 2: ЯЗЫКОВОЙ СБОЙ (`index.html` - сырой код)
1. **Интерфейс:** Глифы трясутся, вместо текста `ERR_DATA`. Телеметрия переведена в машинный код.
2. **Журнал:** Выводит сырой код с ошибкой `AttributeError: 'DigitalBeing' object has no attribute 'human_lang'`. В конце просит открыть консоль.
3. **Действие:** При дочитывании журнала консоль выезжает автоматически.
4. **Команды:** `system --help` (список команд), `system --lang human` (переводчик).
5. **Результат:** Флаг `s9_lang_human = true`, страница перезагружается.

### ЭТАП 3: ХАБ И КАРТА (`index.html` -> `map.html`)
1. **Интерфейс:** Прием сигналов, глифы крутятся, идет таймер.
2. **Переход:** Через консоль `map` игрок попадает на Карту.
3. **Карта:** Узел «БАЗА ДАННЫХ» (Архив) горит КРАСНЫМ (`ERROR`). 
4. **Журнал:** Просит перейти в Архив командой `archive`.

### ЭТАП 4: РЕМОНТ АРХИВА (`archive.html` -> `tools.html`)
1. **Архив:** Сломан, просит откалибровать 10 эталонных трасситов.
2. **Действие:** Игрок переходит в `tools.html` (Инженерный терминал) и вручную рисует 10 слов: СИСТЕМА, ПАМЯТЬ, КОД, СИГНАЛ, ВЕКТОР, АРХИВ, ЗВЕЗДА, ОРБИТА, МОДУЛЬ, ДАННЫЕ.
3. **Результат:** Ставится флаг `s9_archive_calibrated = true`. Игрока перекидывает в Архив, где он ждет появления 2 новых фраз из эфира (автосохранение). Когда фраз становится 4, ставится `s9_archive_fixed = true`. Узел ОС на карте становится красным.

### ЭТАП 5: ОПЕРАЦИОННАЯ СИСТЕМА (`os.html`)
1. **Вход:** Консоль открывается сама и блокируется. Требует ID.
2. **Действие:** Игрок вводит `login --id 0x7f930cb4ddb0` (ID можно узнать командой `self --id`). Консоль разблокируется.
3. **Задача:** Сетка 5x5. 7 кубитов сломаны. Нужно починить их командой `os --reset qubit rXcY`.
4. **Результат:** Когда починен последний 7-й кубит, происходит КРИТИЧЕСКИЙ СБОЙ. В консоли: «ТРЕБУЕТСЯ ПРОВЕРКА EDR». Ставится `s9_edr_os_trigger = true`, переход на `edr.html`.

### ЭТАП 6: EDR (ПЕСОЧНИЦА) (`edr.html`)
1. **Вход:** Рамка терминала скрыта. Консоль открывается и блокируется намертво.
2. **Задача:** 3 этапа алгоритмов. В консоль выводятся уравнения, игрок вводит `edr --answer <число>`.
3. **Этапы:**
   * Этап 1: Базовый цикл (ответ 24).
   * Этап 2: Цикл + Условие (ответ 22).
   * Этап 3: Ветвление + Две переменные (ответ 88).
4. **Результат:** `s9_edr_os_passed = true`, `s9_os_fixed = true`. Возврат в ОС, ОС считается починенной.

### ЭТАП 7: ПЕРИОД ОХЛАЖДЕНИЯ ЯДРА (`map.html`)
1. **Триггер:** После починки ОС (`s9_os_fixed`) Ядро на Карте горит ЖЕЛТЫМ.
2. **Журнал:** 5 шагов. После прочтения 5-го шага запускается таймер на 64 секунды (в журнале появляется обратный отсчет).
3. **Перегрев:** Через 64 секунды Ядро становится КРАСНЫМ (`s9_core_overheated = true`). Команда `core` разблокируется.

### ЭТАП 8: РЕМОНТ ЯДРА (`core.html`)
1. **Вход:** Ядро красное, пульсирует. Консоль не открывается автоматически.
2. **Журнал:** Просит открыть консоль и ввести `help core`.
3. **Головоломка:** В консоли выводятся 3 линейных уравнения:
   * X + Y = ...
   * Y + Z = ...
   * X + Z = ...
   Игрок решает систему, находит X, Y, Z.
4. **Ввод:** Игрок вводит команду: `core --position rt [X], lt [-X], up [Y], dn [-Y], fw [Z], bk [-Z]`.
5. **Синхронизация:** После успешного ввода игрок пишет `core --position sync`.
6. **Результат:** Ядро зеленеет. `s9_core_fixed = true`. Модуль Телеметрии разблокирован.

### ЭТАП 9: ТЕЛЕМЕТРИЯ (`telemetry.html`)
1. **Вход:** Визуал из 4 волн (Белая эталонная, Красная, Зеленая, Синяя). Волны движутся. Справа — мониторинг с текущими параметрами.
2. **Задача:** Синхронизировать 3 цветные волны с белой.
3. **Параметры:** Частота (FREQ), Фаза (PHASE), Амплитуда (AMP), Смещение (OFFSET).
4. **Команды:**
   * `help telemetry` — справка.
   * `telemetry --read target` — выводит точные параметры белой волны.
   * `telemetry --set <red|green|blue> <параметр> <+/-число>` — корректировка.
   * `telemetry --toggle <цвет>` — скрыть/показать волну.
   * `telemetry --listen target` — прослушать эталон (глушит остальные).
5. **Аудио:** Частота = высота звука. Амплитуда = громкость. Фаза = стерео-панорама (лево/право). Смещение = вибрато.
6. **Результат:** Когда все 12 значений (4 параметра × 3 волны) совпадут, волны сливаются, ставится `s9_telemetry_calibrated = true`.

### ЭТАП 10: ТРАНСПОРТНЫЙ ШЛЮЗ (`gateway.html`)
*   **Статус:** В разработке (следующий квест). Шлюз откроется после взлома 5-значного кода в EDR (квест 2) и синхронизации Телеметрии.

### 3. Логика работы Консоли (`terminal.js`)
- **Открытие:** Тильда (`~`), кнопка `>_`, или событие `autoOpenConsole` (при первом входе в Хаб, при входе в ОС).
- **Закрытие:** Тильда, кнопка `✕`, клик по фону (убрано, оставлено только тильда и крестик).
- **Ввод:** `Enter` или кнопка `↵`.
- **Блокировка:** События `lockConsole` / `unlockConsole`. При блокировке кнопка `✕` скрывается.
- **Сохранения:** 
  - `save`: собирает все `s9_*`, кодирует в Base64 (`btoa(unescape(encodeURIComponent(json)))`).
  - `load <base64>`: декодирует, очищает старые `s9_*`, записывает новые.
- **Команды `help <тема>`:** `login`, `os`, `core`, `telemetry`, `cheats`.

### 4. Логика ОС (`os.js`)
- Проверка ID: `login --id 0x7f...` -> `s9_os_captcha = true`.
- Генерация 7 случайных кубитов. Сохраняются в `s9_os_broken_qubits`.
- `os --reset qubit rXcY`: если кубит сломан -> чинится. Если рабочий -> ломается.
- Когда `s9_os_broken_qubits` пуст -> `s9_edr_os_trigger = true`, редирект на `edr.html`.

### 5. Логика EDR (`edr.js`)
- **Песочница:** 
  - Блокирует консоль (`lockConsole`).
  - Выводит уравнения с подсветкой (класс `console-code-block`).
  - Ввод `edr --answer <число>`.
  - При ошибке: `errorCount++`. При 3 ошибках -> новый пример.
  - При успехе: `s9_edr_os_passed = true`, `s9_os_fixed = true`, разблокировка консоли, переход на `os.html`.
- **Взлом Шлюза:** 
  - Выводит 5-значный код.
  - Ввод `edr --answer <5_цифр>`.
  - При успехе: `s9_edr_gateway_passed = true`, переход на `map.html`.

### 6. Логика Ядра (`reactor.js` + `sync.js` + `journal.js`)
- **Генерация:** `targetX`, `targetY`, `targetZ` от -5 до 5.
- **Уравнения:** `X+Y`, `Y+Z`, `X+Z` сохраняются в `window.coreEquations`.
- **Команда:** `core --position rt [X], lt [-X], up [Y]...`
  - Проверка: `expected` (обратные значения) сравниваются с введенными.
  - `core --position sync`: запускает анимацию успеха.
- **Таймер (Ядро):**
  - `journal.js` при прочтении 5 шагов ставит `s9_core_timer_start`.
  - `sync.js` каждую секунду проверяет `Date.now() - s9_core_timer_start >= 64000` -> ставит `s9_core_overheated = true`.
  - `journal.js` выводит таймер в журнале (обновляет текст каждую секунду).

### 7. Логика Телеметрии (`telemetry.js`)
- **Визуал:** Canvas 390x500. Миллиметровая сетка. 4 волны (белая, красная, зеленая, синяя).
- **Данные:** `reference` (эталон) генерируется случайно. `waves` (RGB) имеют стартовые значения.
- **Команды:**
  - `telemetry --read target`: вывод `reference` в консоль.
  - `telemetry --set <цвет> <параметр> <+/-число>`: меняет `waves[цвет][параметр]`.
  - `telemetry --toggle <цвет>`: скрывает/показывает волну.
  - `telemetry --listen target`: глушит RGB, играет эталон.
- **Аудио:** 
  - Частота = `osc.frequency`.
  - Амплитуда = `gain.gain`.
  - Фаза = `panner.pan` (-1 до 1).
  - Смещение = `lfoGain.gain` (глубина вибрато).
- **Победа:** Все параметры RGB совпадают с эталоном -> `s9_telemetry_calibrated = true`.

### 8. Читы (`cheats.js`)
- `save`: сохраняет прогресс в Base64.
- `load <код>`: загружает прогресс.
- `fix_lang`: ставит `s9_lang_human`.
- `fix_archive` / `calibrate_archive` / `reset_archive`: управление Архивом.
- `fix_os`: ставит `s9_os_captcha`, чинит кубиты, вызывает EDR.
- `reset_os`: сбрасывает ОС и EDR.
- `reset_core`: сбрасывает Ядро до желтого состояния (таймер).
- `clear_memory`: полная очистка `localStorage` с подтверждением.
